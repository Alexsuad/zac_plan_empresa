# Documento Guía: Gestión del Léxico en la Comunicación de Sistreg

**Versión:** 1.1
**Fecha:** Mayo de 2026
**Propósito:** Establecer las reglas de lenguaje para que cualquier persona que explique, redacte o revise contenidos de Sistreg comunique con claridad qué problema logístico se resuelve, qué recibe el cliente y cómo se diferencia el proyecto, sin caer en tecnicismos innecesarios ni en ambigüedades que oculten el producto real.

---

## 1. El problema que resuelve esta guía

Sistreg nace desde la experiencia logística real. Su diferencial es entender el proceso, el dolor operativo y el impacto económico antes de proponer tecnología. Ese enfoque es correcto y debe mantenerse.

Sin embargo, durante la evolución del proyecto se detectó un riesgo importante: por evitar parecer una empresa más de IA, automatizaciones genéricas o transformación digital, algunos textos empezaron a ocultar demasiado el producto real que se entrega al cliente.

Ese error genera varios problemas:

* El cliente no sabe qué compra exactamente.
* El entregable se describe con palabras demasiado abstractas: “control operativo”, “trazabilidad”, “tablero”, “alertas”, “formulario”.
* El proyecto puede confundirse con consultoría logística que solo entrega diagnósticos, informes o recomendaciones.
* La tecnología queda tan escondida que el cliente no entiende si recibirá un sistema funcionando o solo una propuesta conceptual.
* La automatización pierde valor percibido porque no se explica qué ocurre automáticamente.

Esta guía sirve para equilibrar el discurso:

> Sistreg debe hablar con profundidad logística para demostrar criterio, y con claridad tecnológica visible para explicar qué recibe y usa el cliente.

---

## 2. Principio general

> **Habla como un especialista logístico que explica una solución tecnológica funcionando, sin enseñar las tripas técnicas.**

Esto significa:

* El cliente debe entender **qué problema operativo se resuelve**.
* El cliente debe entender **qué coste, bloqueo o pérdida se reduce**.
* El cliente debe entender **qué recibe exactamente**.
* El cliente debe entender **qué ve, qué usa y qué ocurre automáticamente**.
* El cliente no necesita saber en primera capa **cómo está construido por dentro**.

La comunicación de Sistreg debe evitar dos extremos:

| Error                                           | Por qué es un problema                                           |
| ----------------------------------------------- | ---------------------------------------------------------------- |
| Vender IA, automatización o tecnología por moda | Hace que Sistreg parezca una agencia genérica de automatización. |
| Ocultar demasiado la tecnología                 | Hace que el cliente no entienda qué compra ni qué recibe.        |

La posición correcta es:

> **Automatización operativa especializada en logística, basada en problemas medibles y soluciones ligeras a medida.**

---

## 3. Dónde aplica esta guía

Esta guía aplica a toda comunicación donde Sistreg explique su propuesta, su valor, sus casos de uso o sus entregables.

Debe aplicarse especialmente en:

* pitch comercial;
* propuesta de valor;
* storytelling comercial;
* casos de entrada;
* caso Doc-to-Cash / control de cobro por evidencia;
* dossier comercial;
* landing page;
* presentaciones de venta;
* propuestas comerciales;
* resumen ejecutivo;
* marketing y ventas;
* marca, comunicación y naming;
* descripción del arranque guiado;
* explicación de entregables;
* apartados del Plan de Empresa donde se explique qué hace Sistreg;
* textos internos que sirvan como base para comunicación externa.

También aplica al cuerpo del proyecto cuando se hable de posicionamiento, diferenciación, operaciones, propuesta de valor, procesos objetivo, diagnóstico o entregables.

No aplica con la misma intensidad a documentación técnica interna, donde sí pueden aparecer herramientas, lenguajes, arquitectura o detalles de implementación si son necesarios.

## 4. Los tres niveles de lenguaje

### 4.1. Léxico logístico profundo

Es el lenguaje que demuestra que Sistreg entiende la operación real del cliente.

Debe usarse principalmente al explicar:

* el problema;
* el proceso actual;
* el flujo logístico;
* el bloqueo operativo;
* la documentación;
* el impacto en tiempo, errores, coste, cobro o margen.

Ejemplos orientativos:

* operación;
* viaje;
* ruta;
* carga;
* descarga;
* CMR;
* POD;
* albarán;
* expediente;
* tráfico;
* administración;
* facturación;
* cobro;
* margen;
* evidencia;
* incidencia;
* validación;
* tarifa;
* reclamación;
* penalización;
* proveedor;
* cliente;
* conductor;
* operación bloqueada;
* factura pendiente;
* documento incompleto;
* operación lista para facturar.

Estos términos son ejemplos, no una lista cerrada.

### 4.2. Criterio de léxico logístico profesional

El léxico logístico profundo no debe funcionar como una lista rígida de palabras obligatorias.

La comunicación de Sistreg debe escribirse desde el criterio de un especialista en logística, cadena de suministro y mejora operativa, usando lenguaje profesional, técnico y moderno cuando aporte claridad, precisión o credibilidad.

Este criterio aplica especialmente a:

* logística integral;
* cadena de suministro;
* transporte terrestre;
* transporte aéreo;
* transporte marítimo;
* comercio exterior;
* almacenaje;
* compras;
* aprovisionamiento;
* suministros;
* filosofía Lean;
* control documental;
* facturación logística;
* operaciones B2B.

El objetivo no es llenar el texto de tecnicismos, sino demostrar dominio real del proceso logístico y explicar el problema con el lenguaje que usaría un responsable de tráfico, operaciones, administración, almacén, comercio exterior, compras o dirección.

Las palabras técnicas deben usarse solo si ayudan a entender mejor:

* el proceso;
* el bloqueo;
* el impacto económico;
* el riesgo operativo;
* el entregable;
* la decisión que debe tomar el cliente.

No deben introducirse términos logísticos solo para aparentar especialización.

### 4.3. Léxico tecnológico superficial, concreto y visible

Es el lenguaje que explica qué recibe el cliente sin entrar en herramientas internas.

Debe usarse principalmente al explicar:

* la solución;
* el entregable;
* la implementación;
* el acompañamiento;
* el soporte;
* qué ocurre automáticamente.

Palabras permitidas y recomendadas cuando correspondan:

* sistema;
* automatización;
* automático;
* automáticamente;
* panel;
* dashboard;
* panel o dashboard accesible por internet;
* acceso con contraseña;
* enlace desde el móvil;
* formulario sencillo;
* carga de evidencias;
* estado por operación;
* lista de viajes;
* vista para administración;
* vista para tráfico;
* aviso automático;
* alerta automática;
* correo automático;
* actualización automática;
* detección automática;
* validación automática;
* instrucciones de uso;
* sesión de formación;
* soporte inicial;
* ajustes de automatizaciones;
* evolución del sistema;
* IA cuando aporta valor;
* inteligencia artificial cuando aporta valor.

Estas palabras son válidas porque describen comportamiento visible para el cliente. No explican las tripas técnicas.

### 4.4. Léxico técnico interno

Es el lenguaje de construcción o implementación interna.

Debe evitarse en la primera capa comercial, salvo que el cliente lo pregunte explícitamente o que se esté trabajando con un perfil técnico.

Ejemplos de términos a evitar en pitch, storytelling, landing, propuesta de valor o explicación inicial:

* Make;
* n8n;
* Zapier;
* Python;
* SQL;
* API;
* webhook;
* backend;
* frontend;
* servidor;
* hosting;
* endpoint;
* JSON;
* XML;
* base de datos relacional;
* macro de Excel;
* script;
* pipeline;
* workflow técnico;
* modelo de IA entrenado;
* fine-tuning;
* vector database;
* prompt;
* embedding;
* despliegue técnico.

Estos términos no están prohibidos para siempre. Pueden usarse en documentación técnica interna o en una conversación técnica si el cliente lo solicita. Lo que se evita es abrir la venta con ellos.

## 5. División por los 8 pasos del storytelling comercial

Sistreg puede explicar sus casos de uso siguiendo una secuencia de 8 pasos.

| Paso                                                             | Función comercial                       | Tipo de léxico recomendado                                  |
| ---------------------------------------------------------------- | --------------------------------------- | ----------------------------------------------------------- |
| 1. Detectar un proceso logístico crítico                         | Ubicar dónde duele la operación         | Léxico logístico profundo                                   |
| 2. Evaluar cómo funciona actualmente                             | Entender el flujo real                  | Léxico logístico profundo                                   |
| 3. Identificar el dolor operativo                                | Nombrar el bloqueo                      | Léxico logístico profundo                                   |
| 4. Traducir el dolor a tiempo, coste, errores, retrasos o margen | Convertir fricción en impacto           | Léxico logístico profundo                                   |
| 5. Presentar el impacto como coste del problema                  | Hacer visible el “número rojo”          | Léxico logístico profundo                                   |
| 6. Proponer una solución ligera y proporcional                   | Decir qué recibe el cliente             | Léxico logístico profundo + tecnología superficial concreta |
| 7. Implementar la solución                                       | Mostrar cómo se pone en marcha          | Léxico logístico profundo + tecnología superficial concreta |
| 8. Acompañar, mantener y mejorar                                 | Explicar continuidad sin sonar complejo | Léxico logístico profundo + tecnología superficial concreta |

Regla práctica:

* Pasos 1 a 5: hablar como especialista logístico.
* Pasos 6 a 8: hablar como especialista logístico que entrega un sistema funcionando, con automatizaciones visibles, sin explicar herramientas internas.

## 6. Palabras permitidas en pasos 6 a 8 y por qué

| Palabra o expresión                         | Por qué usarla                                                                         |
| ------------------------------------------- | -------------------------------------------------------------------------------------- |
| automatización                              | Es el nombre del comportamiento que aporta valor: algo ocurre sin intervención manual. |
| automático / automáticamente                | Describe lo que sucede sin entrar en herramientas.                                     |
| sistema                                     | Término paraguas útil y comprensible.                                                  |
| panel / dashboard                           | El cliente visualiza una pantalla con información organizada.                          |
| acceso por internet / acceso con contraseña | Explica cómo accede el cliente sin hablar de infraestructura.                          |
| enlace desde el móvil                       | El usuario entiende que puede operar desde el móvil sin instalar sistemas complejos.   |
| aviso automático / correo automático        | Aclara que no depende de que alguien se acuerde manualmente.                           |
| estado por operación                        | Explica qué verá el cliente para tomar decisiones.                                     |
| lista de viajes / expedientes               | Concreta el contenido del panel o dashboard.                                           |
| vista para administración / tráfico         | Permite adaptar el mensaje al usuario real.                                            |
| carga de evidencia / subir documento        | Describe una acción concreta del usuario.                                              |
| actualización automática del estado         | Comunica que el sistema mantiene información viva.                                     |
| actualización en tiempo real                | Solo debe usarse si realmente aplica.                                                  |
| detección automática                        | Explica comportamiento inteligente sin hablar de herramientas.                         |
| validación automática                       | Útil si el sistema comprueba estados, documentos o reglas.                             |
| IA / inteligencia artificial                | Solo si realmente se usa y aporta valor. No debe ser el centro del discurso.           |
| instrucciones de uso                        | Entregable tangible.                                                                   |
| formación / sesión online                   | Entregable tangible.                                                                   |
| soporte inicial                             | Servicio de acompañamiento claro.                                                      |
| ajustes / mejoras                           | Refuerza que el sistema puede adaptarse a la operación real.                           |

## 7. Regla del entregable visible

Cada vez que se describa una solución, el texto debe responder de forma clara:

1. ¿Qué ve el cliente?
2. ¿Qué usa el cliente?
3. ¿Qué acción realiza el usuario?
4. ¿Qué ocurre automáticamente?
5. ¿Quién recibe el aviso, estado o resultado?
6. ¿Qué bloqueo logístico reduce?
7. ¿Qué decisión puede tomar el cliente con esa información?

No basta con decir:

> “un panel”, “alertas”, “formulario”, “trazabilidad”, “control operativo”.

Debe explicarse el comportamiento visible.

Ejemplo correcto:

> “El cliente recibe un dashboard accesible por internet con contraseña, donde administración ve qué viajes están listos para facturar, cuáles siguen bloqueados y qué documento falta. El sistema actualiza automáticamente el estado cuando se carga una evidencia y envía un aviso automático al responsable de tráfico si pasan 48 horas sin CMR o POD.”

Ejemplo insuficiente:

> “El cliente recibe una solución de trazabilidad y control operativo para mejorar la eficiencia documental.”

## 8. Profundidad según interlocutor

El nivel de detalle debe adaptarse a la persona que escucha o lee.

| Interlocutor                 | Qué priorizar                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Gerencia / dirección         | Coste del bloqueo, margen, riesgo, control, visibilidad, decisión y continuidad operativa.                                     |
| Tráfico / operaciones        | Viajes, rutas, CMR, POD, evidencias, incidencias, tiempos de espera, responsables y bloqueos.                                  |
| Administración / facturación | Operaciones listas para facturar, documentos pendientes, facturas bloqueadas, cobros, reclamaciones y trazabilidad documental. |
| Almacén                      | Recepción, expedición, ubicaciones, preparación, stock, incidencias, muelles y trazabilidad.                                   |
| Compras / aprovisionamiento  | Proveedor, plazo de entrega, pedido, validación, recepción, incidencias, documentación y cumplimiento.                         |
| Comercio exterior            | Documentación internacional, aduana, Incoterms, transitario, despacho, expediente y trazabilidad documental.                   |
| IT o perfil técnico          | Solo si participa y lo pide: herramientas, integraciones, arquitectura o detalles técnicos.                                    |

El criterio no cambia: se adapta el nivel de profundidad, pero no se transforma el discurso comercial en una explicación técnica interna.

## 9. Ejemplos de frases correctas e incorrectas

### 9.1. Sobre el entregable

| Incorrecto: abstracto o vago               | Correcto: funcional claro sin tecnicismos internos                                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| “Un sistema de control operativo.”         | “Un panel o dashboard accesible por internet con contraseña, donde administración ve el estado de cada operación.”                                                 |
| “Alertas cuando falta un documento.”       | “Una automatización que envía un correo automático al responsable de tráfico si pasan 48 horas sin evidencia de entrega.”                                          |
| “Un formulario para cargar evidencias.”    | “Un enlace sencillo que el conductor abre desde el móvil para subir la foto del CMR o POD; el sistema guarda automáticamente la fecha, hora y operación asociada.” |
| “Una solución de trazabilidad documental.” | “Una vista donde cada operación muestra si el CMR y el POD están recibidos, pendientes o incompletos.”                                                             |
| “Un tablero de seguimiento.”               | “Un dashboard donde gerencia ve cuántas operaciones están listas para facturar, cuántas siguen bloqueadas y cuál es la causa principal del bloqueo.”               |

### 9.2. Sobre el valor y los beneficios

| Incorrecto: abstracto                | Correcto: concreto sin tecnicismos internos                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| “Mejoramos el control operativo.”    | “Administración sabe en un vistazo qué viajes pueden facturarse y cuáles siguen bloqueados por falta de evidencia.” |
| “Digitalizamos tus procesos.”        | “El conductor sube el CMR desde el móvil y el sistema actualiza automáticamente el estado de la operación.”         |
| “Reducimos errores administrativos.” | “El sistema detecta automáticamente qué documentos faltan y avisa antes de que la factura se retrase.”              |
| “Optimizamos la trazabilidad.”       | “Cada expediente muestra qué documento falta, quién debe actuar y si la operación puede pasar a facturación.”       |

### 9.3. Lo que no debe decirse en primera capa comercial

| Frase a evitar                          | Por qué                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------ |
| “Hacemos un script en Python.”          | El cliente no necesita saber el lenguaje usado.                                |
| “Configuramos un webhook en Make.”      | Desplaza la conversación hacia herramientas internas.                          |
| “Te montamos una base de datos en SQL.” | Suena técnico y complejo para una conversación comercial inicial.              |
| “Desplegamos un contenedor Docker.”     | No ayuda a entender el valor logístico.                                        |
| “Integramos vía API REST.”              | Puede ser cierto, pero no es el mensaje inicial para un responsable logístico. |

## 10. Reglas rápidas para escribir y hablar

### Regla 1: Describe comportamientos, no componentes técnicos

Correcto:

> “El sistema envía un correo automático si falta la evidencia.”

Incorrecto:

> “Un proceso programado ejecuta una función que dispara un email.”

### Regla 2: Usa “automatización” sin miedo

Correcto:

> “Incluye automatizaciones que actualizan los estados sin intervención manual.”

Incorrecto:

> “Incluye mejoras funcionales de seguimiento.”

### Regla 3: Si usas IA, que sea verdad y que se entienda para qué

Correcto:

> “Cuando aporta valor, se puede usar inteligencia artificial para apoyar la lectura de documentos y detectar datos faltantes.”

Incorrecto:

> “Solución con IA para transformar la logística.”

### Regla 4: El cliente debe poder visualizar el entregable

Correcto:

> “Recibirá un enlace, un usuario y una contraseña. Al entrar verá una lista con sus operaciones y el estado de cada una.”

Incorrecto:

> “Recibirá una solución tecnológica ligera y proporcional.”

### Regla 5: Si no es necesario decir la herramienta, no la digas

Si el cliente no pregunta por la herramienta interna, no se nombra.

Si el cliente pregunta, se responde con honestidad, pero sin sobrecargar ni convertir la conversación comercial en una explicación técnica.

### Regla 6: Las listas son orientativas

Las listas de esta guía son ejemplos, no una camisa de fuerza. Pueden usarse otros términos logísticos, comerciales o tecnológicos de superficie si ayudan a explicar mejor el caso.

Lo importante no es repetir palabras concretas, sino respetar el criterio:

* precisión logística;
* claridad funcional;
* comportamiento automático visible;
* ausencia de tecnicismos internos innecesarios;
* adaptación al interlocutor empresarial español.

## 11. Aplicación al caso Doc-to-Cash

En el caso Doc-to-Cash / control de cobro por evidencia, la comunicación debe seguir esta lógica:

1. La operación logística ya se realizó.
2. La evidencia documental no está completa, no está validada o no está asociada al expediente correcto.
3. Administración no sabe si puede facturar con seguridad.
4. El equipo pierde tiempo buscando CMR, POD, albaranes, fotos o validaciones.
5. Hay facturas bloqueadas, retrasos, reclamaciones o margen en riesgo.
6. Sistreg propone un sistema ligero con panel o dashboard, carga de evidencias y automatizaciones visibles.
7. El sistema se prueba con viajes reales y documentos reales.
8. El cliente recibe soporte, ajustes y evolución si lo necesita.

Ejemplo de cierre comercial:

> “En este caso, el cliente recibe un dashboard accesible por internet donde administración ve qué viajes están listos para facturar, cuáles siguen bloqueados y qué documento falta. Los conductores o responsables pueden subir evidencias desde un enlace sencillo en el móvil. El sistema actualiza automáticamente el estado de la operación y envía avisos automáticos cuando falta un CMR, POD o albarán después del plazo acordado. No recibe solo un informe: recibe un sistema funcionando para controlar el cierre operación → evidencia → factura → cobro.”

## 12. Comprobación rápida de claridad del entregable

Antes de aprobar un texto comercial o una sección del Plan de Empresa, revisar:

1. ¿El texto demuestra conocimiento logístico real?
2. ¿El cliente entiende qué problema operativo se resuelve?
3. ¿El cliente entiende qué recibe exactamente?
4. ¿Se explica qué ve el cliente?
5. ¿Se explica qué usa el cliente?
6. ¿Se explica qué ocurre automáticamente?
7. ¿Se identifica quién recibe el aviso, estado o resultado?
8. ¿Se usa “automatización” cuando hay comportamiento automático?
9. ¿Se evita vender IA como moda?
10. ¿Se evita ocultar tanto la tecnología que el entregable queda invisible?
11. ¿Se evitan herramientas internas como Make, n8n, Python, SQL o API?
12. ¿El texto está adaptado al público empresarial español?

Si alguna respuesta es “no”, el texto debe revisarse.

---

## 13. Resumen final

> **En los pasos 1 a 5: habla como un especialista logístico que entiende el proceso, el bloqueo y el coste operativo. En los pasos 6 a 8: habla como un especialista logístico que entrega un sistema, panel o dashboard con automatizaciones visibles, sin explicar las herramientas internas que lo construyen.**

Regla final:

> **Logística profunda para demostrar criterio. Automatización visible para explicar valor. Tecnicismos internos solo para documentación interna.**
