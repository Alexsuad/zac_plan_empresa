# Mapa transversal de anexos, investigaciones y validaciones

## Propósito del documento

Este documento convierte la guía humana del Plan de Empresa en una estructura operativa para el futuro sistema agéntico.

Su función es ordenar cuatro cosas:

1. Qué debe responder el emprendedor.
2. Qué debe investigar el sistema.
3. Qué anexos o herramientas se generan.
4. Qué validaciones bloquean o permiten avanzar.

La idea central es evitar que el sistema sea solo un generador de texto. Debe funcionar como una asesoría guiada: pregunta, escucha, investiga, valida, redacta, audita y ayuda a decidir.

---

# 1. Principio general del sistema

El sistema no debe empezar por redactar el plan final.

Debe seguir este flujo:

```text
1. Escuchar al emprendedor.
2. Ordenar la información.
3. Detectar vacíos.
4. Investigar lo que el emprendedor no sabe.
5. Validar con fuentes y evidencias.
6. Generar anexos y herramientas.
7. Redactar cada sección del plan.
8. Auditar coherencia, realismo y respaldo documental.
9. Emitir una conclusión Go / Pivot / No-Go.
```

Este enfoque respeta la lógica de la guía base: el Plan de Empresa es una hoja de ruta viva para investigar, planificar, conocer obstáculos y ganar control sobre el negocio.

---

# 2. Niveles de investigación

No todos los proyectos necesitan el mismo nivel de profundidad.

El sistema debe poder trabajar con tres niveles:

| Nivel                  | Cuándo se usa                                                  | Resultado esperado                                                                        |
| ---------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Investigación ligera   | Primera idea, diagnóstico inicial o plan básico                | Datos rápidos, referentes visibles, primeras señales de mercado                           |
| Investigación media    | Plan presentable ante programa de emprendimiento o tutoría     | Fuentes citables, competencia, precios, cliente, tendencias y riesgos                     |
| Investigación profunda | Banco, subvención, inversor o decisión de inversión importante | Benchmark detallado, datos oficiales, reseñas, normativa, escenarios y evidencias fuertes |

## Regla práctica

* Si el emprendedor solo quiere ordenar una idea, basta una investigación ligera.
* Si necesita presentar el plan en una incubadora o programa de apoyo, se recomienda investigación media.
* Si va a pedir dinero, firmar alquiler, contratar, comprar maquinaria o presentar ante banco/inversor, se recomienda investigación profunda.

---

# 3. Tipos de evidencia que debe guardar el sistema

El sistema debe guardar evidencias para que el plan no quede basado solo en opiniones.

| Tipo de evidencia | Ejemplos                                                                  |
| ----------------- | ------------------------------------------------------------------------- |
| Fuente pública    | INE, ayuntamientos, cámaras de comercio, organismos autonómicos           |
| Fuente sectorial  | Asociaciones, informes, anuarios, colegios profesionales                  |
| Competencia       | Webs, Google Maps, redes, marketplaces, catálogos, precios visibles       |
| Cliente           | Encuestas, entrevistas, reservas, mensajes, pruebas piloto, ventas reales |
| Financiera        | Presupuestos, facturas, tarifas, alquileres, costes de proveedores        |
| Legal             | Normativa, licencias, trámites, consulta a gestoría, consulta municipal   |
| Operativa         | Proveedores, tiempos de producción, capacidad, procesos, herramientas     |
| Reputacional      | Reseñas, quejas frecuentes, comentarios en redes, prensa                  |

Cada evidencia debería guardarse con:

```text
- Nombre de la fuente.
- Enlace o ubicación.
- Fecha de consulta.
- Qué dato aporta.
- Qué sección del plan alimenta.
- Nivel de confianza.
```

# 4.1 Punto 1: Equipo promotor

## Qué debe responder el emprendedor

* Quién promueve el negocio.
* Formación y experiencia.
* Motivación real para emprender.
* Dedicación disponible.
* Roles del equipo.
* Socios o colaboradores.
* Recursos personales.
* Debilidades o límites.
* Red de apoyo.
* Misión, visión y valores iniciales.

## Qué debe investigar el sistema

Normalmente este punto requiere poca investigación externa. La mayor parte depende del emprendedor.

Puede investigar o verificar:

* Perfil profesional público si existe.
* Experiencia demostrable.
* Certificaciones necesarias para la actividad.
* Posibles colaboradores o perfiles externos necesarios.
* Si el equipo cumple requisitos para ayudas específicas.

## Nivel recomendado

| Caso                              | Nivel    |
| --------------------------------- | -------- |
| Autoempleo inicial                | Ligera   |
| Equipo con socios                 | Media    |
| Proyecto con financiación externa | Profunda |

## Fuentes recomendadas

* LinkedIn o portfolio profesional.
* Certificados o diplomas.
* Webs personales o redes profesionales.
* Documentos internos del equipo.
* Convocatorias de ayudas si dependen del perfil del emprendedor.

## Anexos que alimenta

* Ficha del equipo promotor.
* Mapa de habilidades.
* Tabla de roles y dedicación.
* Matriz de capacidades internas.
* Base para el DAFO.
* Base para riesgos humanos.

## Validaciones bloqueantes

| Validación                  | Bloquea si...                                                         |
| --------------------------- | --------------------------------------------------------------------- |
| Identificación del promotor | No se sabe quién lidera el proyecto                                   |
| Dedicación real             | El tiempo disponible no alcanza para ejecutar el plan                 |
| Roles                       | Hay varias personas, pero no se sabe quién hace qué                   |
| Socios                      | Hay socios sin reglas mínimas claras                                  |
| Capacidades                 | El equipo no cubre funciones críticas y no hay apoyo externo previsto |

| Validación           | Bloquea si...                                                  |
| -------------------- | -------------------------------------------------------------- |

# 4.6 Punto 4: DAFO y CAME

## Qué debe responder el emprendedor

* Qué cree que son sus fortalezas.
* Qué reconoce como debilidades.
* Qué oportunidades ve en el entorno.
* Qué amenazas le preocupan.
* Qué acciones cree que puede tomar.

## Qué debe investigar el sistema

Este punto no debe investigar desde cero. Debe usar lo ya investigado en 3.1, 3.2 y 3.3.

Debe validar:

* Que las fortalezas y debilidades sean internas.
* Que las oportunidades y amenazas sean externas.
* Que cada punto venga de una evidencia o respuesta previa.
* Que el DAFO no sea genérico.
* Que el CAME convierta el análisis en acciones.

## Nivel recomendado

| Caso                   | Nivel                    |
| ---------------------- | ------------------------ |
| Cualquier plan         | Media                    |
| Plan para financiación | Profunda en trazabilidad |

## Fuentes recomendadas

* Análisis externo.
* Estudio de mercado.
* Análisis interno.
* Evidencias recopiladas.
* Benchmark.
* Riesgos detectados.

## Anexos que alimenta

* Matriz DAFO.
* Matriz CAME.
* Priorización estratégica.
* Base para objetivos.
* Base para matriz de riesgos.

## Validaciones bloqueantes

| Validación    | Bloquea si...                           |
| ------------- | --------------------------------------- |
| Trazabilidad  | El DAFO no sale de los análisis previos |
| Especificidad | Los puntos son genéricos                |
| Clasificación | Se confunde interno con externo         |
| Acción        | El CAME no propone acciones concretas   |
| Priorización  | Hay demasiados puntos sin jerarquía     |

# 6. Validaciones bloqueantes principales

Estas validaciones deben funcionar como gates. Si fallan, el sistema no debería cerrar la sección como aprobada.

| Gate             | Pregunta                                                 | Bloquea avance hacia          |
| ---------------- | -------------------------------------------------------- | ----------------------------- |
| Gate idea clara  | ¿Se entiende qué vende el negocio?                       | Mercado, marketing, finanzas  |
| Gate cliente     | ¿Hay cliente objetivo definido?                          | Marketing, ventas, viabilidad |
| Gate problema    | ¿Hay problema/necesidad real?                            | Propuesta de valor            |
| Gate competencia | ¿Hay competidores o sustitutos identificados?            | Benchmark, DAFO               |
| Gate fuentes     | ¿Hay fuentes mínimas de mercado?                         | Estudio de mercado            |
| Gate capacidad   | ¿Puede entregar lo que promete?                          | Ventas, finanzas              |
| Gate precio      | ¿El precio cubre costes y tiene sentido para el cliente? | Plan financiero               |
| Gate cobro       | ¿Está claro cómo y cuándo se cobra?                      | Tesorería                     |
| Gate legal       | ¿Permisos críticos identificados?                        | Implantación y GO             |
| Gate ayudas      | ¿Existe escenario sin ayudas?                            | Viabilidad financiera         |
| Gate riesgos     | ¿Riesgos altos con mitigación?                           | Conclusión final              |
| Gate coherencia  | ¿Las secciones no se contradicen?                        | Documento final               |

# 7. Separación entre responder, investigar, redactar y auditar

El sistema debe separar claramente cuatro funciones.

## 7.1 Responder

Lo hace principalmente el emprendedor.

Aporta:

* idea;
* motivación;
* experiencia;
* recursos;
* contactos;
* visión;
* límites personales;
* primeros clientes;
* decisiones internas.

## 7.2 Investigar

Lo hace el sistema o agente investigador.

Busca:

* datos de mercado;
* competidores;
* precios;
* reseñas;
* normativa;
* ayudas;
* costes;
* proveedores;
* salarios;
* tendencias.

## 7.3 Redactar

Lo hace el agente redactor integrador.

Convierte información validada en:

* secciones del plan;
* anexos;
* tablas;
* conclusiones parciales;
* resumen ejecutivo.

## 7.4 Auditar

Lo hace el agente auditor.

Evalúa:

* completitud;
* especificidad;
* coherencia;
* realismo;
* respaldo documental;
* exigencia de banco/inversor;
* riesgos;
* contradicciones.

# 8. Flujo recomendado del sistema agéntico

```text
1. Intake inicial
   ↓
2. Banco vivo de información
   ↓
3. Diagnóstico de tipo de negocio
   ↓
4. Preguntas por bloque
   ↓
5. Investigación ligera/media/profunda
   ↓
6. Validación con el emprendedor
   ↓
7. Generación de anexos parciales
   ↓
8. Redacción de sección
   ↓
9. Auditoría de sección
   ↓
10. Corrección si aplica
   ↓
11. Integración del plan completo
   ↓
12. Auditoría final de trazabilidad
   ↓
13. Decisión Go / Pivot / No-Go
```

# 9. Banco vivo de información

El sistema debe mantener un banco central de datos del proyecto.

Debe guardar:

* respuestas del emprendedor;
* supuestos;
* decisiones confirmadas;
* evidencias;
* fuentes;
* hipótesis;
* riesgos;
* anexos;
* versiones;
* pendientes;
* validaciones superadas o fallidas.

Cada dato importante debe tener estado:

| Estado                     | Significado                      |
| -------------------------- | -------------------------------- |
| Confirmado por emprendedor | El emprendedor lo validó         |
| Investigado con fuente     | El sistema encontró respaldo     |
| Hipótesis                  | Se cree, pero no está comprobado |
| Pendiente                  | Falta información                |
| Contradictorio             | Choca con otro dato              |
| Bloqueante                 | Impide avanzar sin resolver      |
