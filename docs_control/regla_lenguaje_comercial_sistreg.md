# Regla de lenguaje comercial de Sistreg

## Propósito

Asegurar que los textos comerciales de Sistreg expliquen con claridad qué problema logístico se resuelve y qué recibe exactamente el cliente, sin caer en dos errores:
1. vender tecnología genérica o IA por moda;
2. ocultar tanto la tecnología que el cliente no entiende qué compra.

## Rol experto logístico

El lenguaje comercial de Sistreg debe escribirse desde el criterio de un especialista en logística, cadena de suministro y mejora operativa. El texto debe usar léxico profesional, técnico y moderno del sector cuando aporte claridad, precisión o credibilidad, especialmente en logística, transporte terrestre, transporte aéreo, transporte marítimo, comercio exterior, almacenaje, compras, aprovisionamiento, suministros, filosofía Lean, control documental y operaciones B2B.

El objetivo no es llenar el texto de tecnicismos, sino demostrar dominio real del proceso logístico y explicar el problema con el lenguaje que usaría un responsable de tráfico, operaciones, administración, almacén, comercio exterior o dirección.

## Regla principal

En los pasos de diagnóstico y dolor se usa léxico logístico profundo para demostrar criterio y conocimiento del sector.
En los pasos de solución, entregable, implementación y soporte se usa léxico logístico profundo combinado con léxico tecnológico superficial, concreto y orientado a comportamiento automático para explicar el valor real.

## Aplicación por etapa

| Etapa | Tipo de lenguaje | Objetivo |
|---|---|---|
| Problema, diagnóstico y coste del bloqueo | Léxico logístico profundo | Demostrar conocimiento real de la operación. |
| Solución, entregable e implementación | Léxico logístico profundo + tecnología superficial concreta | Explicar qué recibe y usa el cliente. |
| Documentación técnica interna | Léxico técnico interno | Explicar cómo se construye, solo para uso interno. |

## Léxico logístico profundo

Las listas de términos son ejemplos orientativos, no una camisa de fuerza. Pueden usarse otros términos logísticos profesionales si encajan con el contexto, el cliente y el proceso analizado. No deben introducirse palabras técnicas solo por aparentar especialización.

Usar palabras como:
- operación;
- viaje;
- ruta;
- carga;
- descarga;
- expediente;
- tráfico;
- administración;
- facturación;
- cobro;
- margen;
- cliente;
- proveedor;
- conductor;
- CMR;
- POD;
- albarán;
- evidencia de entrega;
- incidencia;
- validación de tarifa;
- documento pendiente;
- operación bloqueada;
- operación lista para facturar;
- expediente abierto;
- reclamación;
- retraso de facturación;
- horas de seguimiento;
- reproceso;
- pérdida de margen.

## Léxico tecnológico superficial permitido

Usar palabras como:
- sistema;
- automatización;
- automático;
- automáticamente;
- dashboard;
- detección automática;
- validación automática;
- actualización automática;
- aviso automático;
- panel;
- panel accesible por internet;
- acceso con contraseña;
- enlace desde el móvil;
- formulario sencillo;
- carga de evidencias;
- estado por operación;
- vista para administración;
- vista para tráfico;
- lista de viajes;
- soporte inicial;
- ajustes de automatizaciones;
- evolución del sistema;
- IA cuando aporta valor;
- inteligencia artificial cuando aporta valor.

## Léxico tecnológico permitido con cautela

Estas palabras pueden usarse solo si el caso lo justifica:
- IA;
- inteligencia artificial;
- sistema inteligente;
- automatización avanzada;
- análisis automático;
- clasificación automática;
- extracción de información.

Regla:
No abrir el discurso comercial desde IA. La IA se menciona solo como medio, no como promesa central. Se permite usar palabras como sistema, automatización, automático, dashboard, panel, aviso automático, validación automática, actualización automática e IA cuando aporta valor. Estas palabras sí son válidas porque describen comportamiento visible para el cliente.

## Léxico no permitido en pitch comercial inicial

Evitar en textos comerciales de primera capa (herramientas internas o detalles de construcción):
- Make;
- n8n;
- Python;
- SQL;
- API;
- webhook;
- backend;
- frontend;
- endpoint;
- servidor;
- base relacional;
- macro;
- script de Python;
- pipeline;
- OCR específico;
- modelo de IA;
- prompt;
- embedding;
- integración vía API.

Estas palabras pueden usarse en documentación técnica interna o en conversaciones técnicas si el cliente las solicita.

## Regla del entregable visible

Cada vez que se describa una solución, el texto debe responder:
1. Qué ve el cliente.
2. Qué usa el cliente.
3. Qué ocurre automáticamente.
4. Quién recibe el aviso o resultado.
5. Qué mejora en el flujo logístico.

## Ejemplo correcto

“El cliente recibe un panel accesible por internet con contraseña, donde administración ve qué viajes están listos para facturar, cuáles siguen bloqueados y qué documento falta. El sistema actualiza automáticamente el estado cuando se carga una evidencia y envía un aviso automático a tráfico si pasan 48 horas sin CMR o POD.”

## Ejemplo incorrecto

“El cliente recibe una solución de trazabilidad y control operativo para mejorar la eficiencia documental.”

## Regla final

Logística profunda para demostrar criterio.
Automatización visible para explicar valor.
Tecnicismos internos solo para documentación interna.
